# Тема 8. Синтаксис `async`/`await` і пагінація. Домашня робота

Цей проєкт є реалізацією веб-застосунку для пошуку зображень за ключовим словом з використанням публічного API [Pixabay](https://pixabay.com/api/docs/). Проєкт створено за допомогою модульного підходу для написання коду на *JavaScript* і зібрано інструментом [Vite](https://vitejs.dev/).

## Технологічний стек
- **HTML5**, **CSS3** - з використанням CSS-змінних та **Flex/Grid**;
- **JavaScript** - **ES6+** модулі, `async`/`await`, **Promises**;
- [**Vite**](https://vitejs.dev/) - збирач проєкту згідно вимог до ДЗ;
- [**Axios**](https://axios-http.com/) - для здійснення HTTP-запитів;
- [**iziToast**](https://marcelodolza.github.io/iziToast/) - для сповіщень та обробки помилок;
- [**SimpleLightbox**](https://simplelightbox.com/) - для перегляду зображень у модальному вікні-галереї;
- [CSS-Loader](https://cssloaders.github.io/) - стилізований індикатор завантаження.

## Опис роботи
Додаток дозволяє користувачеві ввести ключове слово у форму пошуку та отримати галерею з **15** зображень за один запит.
- **Пагінація** : зроблена у форматі *"хочу ще"*. Якщо знайдено більше ніж `15` зображень, під галереєю з'являється кнопка **`Load more`**. При її натисканні відбувається асинхронний запит наступної порції (сторінки) зображень і ці нові результати плавно доєднуються в кінці, як продовження галереї.
- **Плавний скрол** : Після кожного такого *"дозавантаження"* сторінка автоматично і плавно прокручується донизу на висоту двох карток (за допомогою `getBoundingClientRect` та `window.scrollBy(…)`).
- **Кінець колекції** : Коли користувач доходить до ліміту доступних результатів, кнопка **`Load more`** зникає, і з'являється сповіщення через бібліотеку `iziToast` з повідомленням *"We're sorry, but you've reached the end of search results."*

Під час очікування відповіді від сервера відображається стилізований індикатор завантаження.
При кліку на мініатюру відкривається повнорозмірне зображення з інформацією про нього завдяки `SimpleLightbox`.

## Авторські доповнення та покращення *(Custom Enhancements)*
Під час розробки було вирішено не обмежуватися трохи сухими вимогами технічного завдання і додати низку креативних рішень для створення по-справжньому якісного продукту:

1. **Дизайн та Стилізація:**
   - Впроваджено систему CSS-змінних (`--main-color`, `--second-color`, `--third-color`) для підтримки цілісної кольорової теми.
   - Замість звичайного тексту для блоку інформації інтегровано **SVG-іконки** для лайків, переглядів, коментарів та завантажень.
   - Додано плавні hover-ефекти з використанням `box-shadow` та `transform: scale()`.
   - Використано властивість `aspect-ratio: 8 / 5` для формування пропорційної сітки карток *(в попередньому завданні це була пропорція 3/2)*.
   - Візуально допрацьовано модальне вікно `SimpleLightbox` : додано затемнення фону і трохи blur-ефекту для покращення контрастності вигляду фотографії *(просто люблю темну тему, хехе)*.

2. **Наскрізна нумерація результатів *(Image Counter)*:**
   - У верхньому правому куті кожної картки додано маленький стилізований напівпрозорий лічильник, який вказує порядковий номер картинки (1, 2, … 37… 112…). Логіка нумерації зберігається при пагінації і скидається лише при новому пошуку *(реалізовано через інкремент у циклі `for...of`)*.

3. **Статистика пошуку та керування станом **UI**:**
   - Праворуч від форми пошуку додано інформаційний блок: він показує, скільки картинок нам дозволено завантажити (`Query limit: X`) та скільки їх загалом існує в базі (`Of total: Y`).
   - Надійно пропрацьовано зникнення кнопки **`Load more`** при помилкових чи порожніх запитах, щоб уникнути *"кнопок-привидів"* від попередніх пошуків.

4. **Глибока робота з API Pixabay *(ліміти та Data Drift)*:**
   - **Дослідження лімітів** : Розрахунок пагінації спирається виключно на параметр `totalHits` (максимум 500 для безкоштовних акаунтів), а не `total`. Це гарантує, що застосунок ніколи не спробує запросити заблоковану 501-шу картинку і не впаде з помилкою `400 Bad Request`.
   - **Вирішення проблеми дублікатів** : При використанні пагінації за замовчуванням (сортування за популярністю) динамічна зміна рейтингів призводить до того, що одні й ті самі картинки *переповзають* між підвантаженими сторінками. Фактично з'являються дублікати. Щоб вирішити цю проблему без відсіювання дублікатів під час обробки чергового запиту, яке б "відкусило" кілька карток і порушило б цілісність 5-колонкової сітки галереї, в запит додано параметр `order: 'latest'`. Це забезпечує стабільну і передбачувану видачу без візуальних дірок.

5. **Вирішення багів сторонніх бібліотек:**
   - Значення для ініціалізації `SimpleLightbox` адаптовано до сучасного стандарту ES-модулів. Обійдено незвичний баг методу `.refresh()` у `simple-lightbox.esm.js` (помилка `Class constructor cannot be invoked without 'new'`). Це вирішено шляхом використання методу `.destroy()` та повторної ініціалізації екземпляра класу під час нових запитів.
